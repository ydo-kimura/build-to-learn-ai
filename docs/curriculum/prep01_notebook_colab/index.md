# Prep 1: Notebook／Colab の基礎

この Prep では、Google Colaboratory（以下 Colab）を使って、コードを自分で入力し、順番に実行し、結果を確認する方法を学びます。

Notebook は、上から下まで一度に完成させるプログラムとは少し違います。コードを小さな「セル」に分けて実行できる一方で、実行した順番によって、画面に見えているコードとランタイム内の値が食い違うことがあります。この違いを自分で確かめることが、この Prep の中心です。

## この Prep の到達目標

- コードセルとテキストセルを作成、編集、実行、削除できる
- セルの出力と実行状態を確認できる
- Notebook とランタイムの違いを説明できる
- セルを上から順に実行する理由を説明できる
- エラーを確認し、コードを直して再実行できる
- ランタイムを再起動し、すべてのセルを最初から実行できる

## スキップ判定

新しい Colab Notebook で、次の操作を説明なしで行えるか確認してください。

1. コードセルとテキストセルを1つずつ作る
2. 2つのコードセルで同じ変数を使い、実行順によって出力が変わる理由を説明する
3. ランタイムを再起動し、変数が消えたことを確認する
4. エラーの最後の行を読み、コードを直して再実行する
5. 「すべてのセルを実行」で、上から順に同じ結果を再現する

すべて行えて、なぜその結果になるか説明できる場合は、この Prep をスキップできます。操作できない項目や説明できない項目が1つでもある場合は、実践まで進めてください。

## 学習を始める前の準備

Colab へのアクセスと新しい Notebook の作成は、[学習環境とAPI準備（Appendix）](../appendix/index.md)の「Google Colaboratory での学習の進め方」を参照してください。この Prep では、作成済みの空の Notebook を使います。

## 1. Notebook はセルを並べたファイル

Notebook には、主に2種類のセルがあります。

| セル         | 書くもの           | 実行するとどうなるか                                     |
| ------------ | ------------------ | -------------------------------------------------------- |
| コードセル   | Python のコード    | コードが実行され、必要に応じてセルの下に出力が表示される |
| テキストセル | 見出し、説明、メモ | Markdown が整形され、読みやすい文章として表示される      |

Colab では、画面上部の「+ コード」と「+ テキスト」からセルを追加できます。セルをクリックすると編集でき、コードセルの左側にある実行ボタン、または `Shift + Enter` で実行できます。

セルを選択したときに表示されるツールバーやその他メニューから、セルの移動や削除もできます。削除してしまった場合は、すぐに「編集」メニューの「セルの操作を元に戻す」を使うと戻せます。

### コードセルと出力

次のコードを1つのコードセルに入力して実行します。

```python
message = "最初の実行"
print(message)
```

セルの下に次の出力が表示されます。

```text
最初の実行
```

コードセルの左側には、未実行、実行中、実行済みを区別する表示があります。実行番号が表示される画面では、その番号は「Notebook 内の何番目のセルか」ではなく、「現在のランタイムで何番目に実行したか」を表します。

同じセルをもう一度実行すると、出力は新しい実行結果に置き換わり、実行番号も更新されます。

### テキストセル

次の内容をテキストセルに入力します。

```markdown
## 実験メモ

このセルには、コードの目的や結果から分かったことを書く。
```

テキストセルを実行すると、`##` は見出しとして表示されます。学習中は、コードだけでなく「実行前の予想」と「結果から分かったこと」をテキストセルに残してください。

## 2. Notebook とランタイムは別のもの

Notebook は、セルに書いたコードや文章を保存するファイルです。ランタイムは、そのコードを実行し、作成した変数を一時的に覚えている実行環境です。

次の2つのコードセルを上から順に実行します。

セルA:

```python
status = "1回目"
```

セルB:

```python
print(status)
```

出力は次のようになります。

```text
1回目
```

セルAを実行したとき、ランタイムは `status` という変数と、その値を記憶します。セルBは、ランタイムが覚えている値を読み取って表示しています。

### 画面のコードとランタイム内の値が食い違う例

セルAのコードを次のように編集します。ただし、まだ実行しません。

```python
status = "2回目"
```

この状態でセルBだけをもう一度実行すると、出力はまだ次のままです。

```text
1回目
```

画面上のセルAには `"2回目"` と書かれていますが、編集しただけではランタイム内の値は変わりません。セルAを実行してからセルBを実行すると、初めて `2回目` と表示されます。

このような食い違いを避ける基本は、セルを上から順に実行することです。

## 3. 再起動と「すべてのセルを実行」

ランタイムを再起動すると、変数など、ランタイムが一時的に覚えていた状態は消えます。Notebook に書いたセルは残ります。

1. 「ランタイム」メニューから「セッションを再起動」を選ぶ
2. セルAを実行せず、セルBの `print(status)` だけを実行する
3. `NameError` が表示されることを確認する

再起動後のランタイムは `status` をまだ知らないため、セルBだけでは実行できません。セルA、セルBの順に実行すると、再び表示できます。

Notebook 全体を再現できるか確認するときは、「ランタイム」メニューの「すべてのセルを実行」を使います。途中のセルだけを先に実行しないと動かない Notebook は、上から順に再現できる状態になっていません。

ブラウザを閉じた場合や、操作しない時間が続いて Colab の接続が切れた場合も、ランタイムの状態は失われることがあります。保存された Notebook が残っていても、変数や追加した一時ファイルまで同じ状態で残るとは限りません。

## 4. エラーは直す場所を知らせる出力

次のセルを、新しいランタイムでそのまま実行します。

```python
print(course_name)
```

`course_name` はまだ作られていないため、最後に次のようなエラーが表示されます。

```text
NameError: name 'course_name' is not defined
```

長いエラーが表示されたときは、まず最後の行を確認します。ここでは、`course_name` という名前が定義されていないことが原因です。

同じセルを次のように修正して、もう一度実行します。

```python
course_name = "AIカリキュラム"
print(course_name)
```

```text
AIカリキュラム
```

エラーが出ても、Notebook を作り直す必要はありません。原因を確認し、コードを修正し、そのセルから再実行できます。ただし、修正後は最後にランタイムを再起動して「すべてのセルを実行」し、上から順に再現できるかも確認します。

## 5. Notebook の保存とコピー

Colab で作成した Notebook は Google Drive に保存され、編集内容も自動保存されます。元の Notebook を残して別の実験をしたい場合は、「ファイル」メニューから「ドライブにコピーを保存」を選びます。

保存されるのは、セルに書いたコード、文章、保存時点の出力などです。ランタイムが覚えている変数そのものを保存する操作ではありません。別の日に Notebook を開いたら、上から順にセルを実行して状態を作り直します。

## 6. 実践前にAIアシストをオフにする

ここからの実践では、Colab のAIによるコード補完や生成をオフにします。補完された答えを写すのではなく、自分でセルを作り、出力を予想し、エラーを読んで直すためです。

1. Colab の「ツール」メニューから「設定」を開く
2. 「AI アシスタンス」を選ぶ
3. AI コーディング機能を無効にする、または同意を取り消してAI機能を非表示にする
4. 設定画面を閉じ、入力中にAIの候補が表示されないことを確認する

AI機能が最初から表示されていない場合、この操作は不要です。画面やアカウントによって表示が異なる場合は、[Google Colab 公式FAQ](https://research.google.com/colaboratory/faq.html?hl=ja-jp)も確認してください。

AIアシストはカリキュラム全体で禁止するものではありません。この実践を終えた後は、同じ設定画面から必要に応じて再び有効にできます。

## 7. 実践

空の Notebook を用意し、次の Step を上から順に行ってください。出力例はまだ見ず、各 Step で予想をテキストセルに書いてから実行します。

### Step 1: コードセルとテキストセルを作る

1. テキストセルを追加し、見出し「Notebook 実行実験」と、実験の目的を書いて実行してください。
2. その下にコードセルを追加し、次のコードを実行してください。

```python
note = "最初のセルを実行しました"
print(note)
```

3. 表示された出力と、コードセルが実行済みだと判断できる表示を記録してください。
4. 空のコードセルをもう1つ追加して削除し、「編集」メニューの「セルの操作を元に戻す」で復元してください。

### Step 2: 実行順で値が変わることを確かめる

次のセルAとセルBを作ります。

セルA:

```python
color = "青"
```

セルB:

```python
print(color)
```

1. セルA、セルBの順に実行し、出力を記録してください。
2. セルAを `color = "赤"` に編集します。ただし、まだ実行しません。
3. この状態でセルBだけを実行すると何が表示されるか予想してください。
4. セルBを実行し、予想と結果を比較してください。
5. セルA、セルBの順に実行し直し、出力がどう変わるか確認してください。

### Step 3: ランタイムを再起動する

1. 「ランタイム」メニューから「セッションを再起動」を選んでください。
2. 再起動直後にセルBだけを実行すると何が起きるか予想してください。
3. セルBを実行し、エラーの最後の行を記録してください。
4. セルA、セルBの順に実行し、エラーが解消することを確認してください。

### Step 4: エラーを直して再実行する

新しいコードセルに、次のコードを入力して実行します。

```python
print(topic)
```

1. 表示されるエラーの種類を記録してください。
2. エラーの最後の行から、何が足りないか説明してください。
3. 同じセルを、`topic` に `"Notebook"` を代入してから表示するコードに修正してください。
4. 修正したセルを再実行し、`Notebook` と表示されることを確認してください。

### Step 5: 上からの再実行で再現する

1. ランタイムをもう一度再起動してください。
2. 「すべてのセルを実行」を選んでください。
3. 途中でエラーが止まらず、最後まで同じ結果を再現できるか確認してください。
4. エラーで止まった場合は、どのセルより前に必要な変数が作られていないか調べ、セルの順番またはコードを直してください。

### Step 6: 保存とコピーを確認する

1. Notebook の名前を変更してください。
2. Google Drive に保存済みであることを確認してください。
3. 「ファイル」メニューから「ドライブにコピーを保存」を選び、コピーを作成してください。
4. 元の Notebook とコピーが別のファイルであることを確認してください。

### ヒント

- 編集しただけでは、ランタイム内の値は変わりません。
- `NameError` は、使用した名前をランタイムがまだ知らないときに表示されます。
- 「すべてのセルを実行」で途中停止する場合は、停止したセルより上の順番を確認します。
- 保存された Notebook と、現在接続しているランタイムの状態は別です。
